## 0. Поправка: маршрута «установщик Windows» не существует

Ранее в этом документе предлагались два маршрута: Docker **или** установщик Windows без перезагрузки.
**Второй вариант невозможен.** Это моя ошибка: я предложил его до того, как был проверен сам пакет.

Проверено по официальной документации версий 17.4, 17.8, 18.0 и 18.3 — список сборок
в селекторе «Выберите ОС» везде одинаковый:

```
ALT Linux 11
Astra Linux 1.7
Astra Linux 1.8
Astra Linux 1.8 - CLR
RedOS 7.3
RedOS 8.0
Ubuntu 22.04 LTS
Ubuntu 24.04 LTS
Ubuntu 24.04 LTS - CLR
Docker Ubuntu 22.04 LTS
Windows 10/11 (Клиент)          <- единственная сборка под Windows, и это КЛИЕНТ
```

**Вывод: сервера Digital Q.DataBase под Windows не существует.** Все серверные сборки — Linux
или Docker на Ubuntu 22.04. Значит, на этой машине единственный путь — **Docker + WSL2**,
с установкой WSL2 и перезагрузкой. Обхода нет.

## 1. Что фактически скачано

Файл: `digital-q-database-winclient-18-18.2.26061101.tar.gz`, 195,9 МБ.
Содержимое проверено командой `tar -tzf`:

```
digital-q-database-winclient-18-18.2.26061101/
+-- qdatabase-winclient-18-18.2.26061101.exe       <- установщик, русский
+-- qdatabase-winclient-18-18.2.26061101-en.exe    <- установщик, английский
+-- README_WINDOWS.txt
`-- два PDF-руководства
```

Серверных бинарников нет. `README_WINDOWS.txt` прямо говорит, что пакет даёт только:

- **Мастер переноса БД**
- **Мастер сравнения БД**
- **qclient.exe** — терминальный клиент диалекта Oracle (PL/SQL)

и что подключаться нужно к *удалённому* серверу:
`qclient.exe qdb://SYSDBA:SYSDBA@ServerName:1521/qdbora`

**Два факта, которые пригодятся:**

1. Актуальная версия сейчас **18.2**, а не 17.x, о которой я писал ранее.
2. **Мастер переноса БД и Мастер сравнения БД — это ровно те инструменты, о которых идёт речь
   в конкурсном задании.** Когда появится сервер, их можно установить и показать как
   дополнительное доказательство. Но им нужен сервер, к которому они подключаются.

## 2. Что нужно запросить у «Диасофта»

Нужен **серверный** пакет, а не клиентский.

### Вариант А — Docker (рекомендуется)

Образ под Ubuntu 22.04, документированный быстрый старт:

```
docker load -i docker-qdatabase64xid-18-<сборка>-ubuntu22_x86_64.tar.gz
docker run -it --platform=linux/amd64 --restart always --name=qdatabase-18 \
  --shm-size=1g -p 5445:5445 -p 1433:1433 -p 1521:1521 \
  -v qdb_data:/var/lib/qdatabase-18/data qdatabase_docker
```

Требует WSL2 на этой машине. Виртуализация в BIOS уже включена (проверено), так что
установка WSL2 должна пройти. Нужны UAC и перезагрузка.

### Вариант Б — Linux-пакет на виртуальной машине

`qdatabase-18-18.x-ubuntu22.04-x86_64.deb` или `.rpm` для ALT/RedOS, на любой Linux VM.
Ничего в Windows ставить не нужно, но нужна отдельная машина с Linux.

## 3. Что уже готово с нашей стороны

Подготовлено так, чтобы перенос был одним запуском скрипта:

- `db/migrations/001_initial.sql`, `db/migrations/002_auth_sessions.sql` — переносимые,
  без расширений, без триггеров и хранимых процедур.
- `db/seed/data.mjs` — демо-набор с фиксированными UUID.
- `scripts/migrate.mjs` — применяет миграции к любому `DATABASE_URL` (проверен, идемпотентен).
- `scripts/qdb-02-identify.mjs` — отчёт о целевом экземпляре без утечки паролей.
- `scripts/qdb-03-compat.mjs` — 15 проб совместимости. Против эталонного PostgreSQL 17.10: **15/15 PASS**.
- `scripts/qdb-04-migrate.mjs` — перенос одной транзакцией, с предохранителем от самоуничтожения
  источника при совпадении URL.
- `scripts/qdb-05-verify.mjs` — 25 проверок сверки. «Источник против себя»: **25/25 PASS**.
- API работает через драйвер `pg`, то есть через тот же PostgreSQL-протокол, который
  Digital Q.DataBase отдаёт на порту 5445. Переключение цели — это смена `DATABASE_URL`.

## 5. Правило честности

Пока QDB-02 … QDB-05 не выполнены и артефакты не сохранены, в выступлении **нельзя** говорить
«перенесла на Digital Q.DataBase» и «демонстрация идёт на Digital Q.DataBase».

Допустимая и при этом сильная формулировка:

> «Проект написан под PostgreSQL. Схема — переносимый PostgreSQL DDL без расширений.
> Digital Q.DataBase нативно поддерживает этот диалект, процедура переноса написана
> и протестирована: 25 проверок сверки пройдено на эталонной базе. Когда откроется
> целевой экземпляр, переключение — это одна переменная окружения.»

Это соответствует `07_DEMO_AND_PITCH.md` §1 «Главное правило достоверности» и §10.

| Шаг | Что делаю | Критерий успеха |
|---|---|---|
| QDB-02 | Поднять экземпляр, снять `SELECT version()`, параметры сборки | Отчёт без секретов |
| QDB-03 | Прогнать 15 проб совместимости | Все PASS/FAIL записаны |
